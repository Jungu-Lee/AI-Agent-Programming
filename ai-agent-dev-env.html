1개요 및 사전 준비사항

본 자료는 인공지능에이전트프로그래밍의 실습 기반을 구글 콜랩(Colab) 환경뿐 아니라, 학교 실습실 PC 또는 교사·학생 개인 PC에서 오프라인으로도 구동 가능한 로컬 LLM 환경으로 확장하기 위한 절차를 다룬다. 유료 API 키 발급 없이 오픈소스 경량 모델(qwen3.5:4b)을 로컬에서 구동함으로써, 인터넷 상황이나 예산 제약과 무관하게 AI 에이전트의 핵심 원리(도구 호출, RAG)를 실습할 수 있도록 하는 것이 목적이다.

📌 이 가이드의 아키텍처: Ollama는 항상 호스트에 네이티브 설치

Ollama 자체는 Docker 컨테이너로 띄우지 않는다. 모든 운영체제(Windows·macOS·Linux)에서 Ollama를 PC에 직접 설치해 사용한다. 특히 macOS(Apple Silicon)는 Docker 컨테이너 안에서 Metal GPU 가속을 받을 수 없어 CPU로만 동작하는 근본적인 한계가 있으므로, Ollama를 네이티브로 설치해야만 Mac에서도 정상적인 속도가 나온다.

경로 A. 완전 로컬 환경 — Ollama + Python(로컬 설치)을 PC에 직접 구성 (가장 간단, 개인 실습에 적합)

경로 B. 하이브리드(Docker) 환경 — Ollama는 호스트에 네이티브 설치하고, JupyterLab + 에이전트 라이브러리만 Docker 컨테이너로 구성 (실습실 전체에 동일한 파이썬 환경을 배포하고 싶을 때 적합, Ollama는 항상 각 PC의 성능을 그대로 사용)

💡 왜 Ollama를 컨테이너화하지 않는가

Docker Desktop for Mac은 Apple Silicon의 Metal GPU를 컨테이너로 전달(passthrough)하지 못한다. 이 때문에 Ollama를 컨테이너 안에서 실행하면 Mac에서 항상 CPU로만 동작하여 네이티브 설치보다 체감상 3~6배 느려진다. 반면 Ollama를 호스트에 직접 설치하면 Windows(NVIDIA GPU)·macOS(Metal)·Linux(NVIDIA GPU) 모두에서 각 OS가 지원하는 하드웨어 가속을 있는 그대로 활용할 수 있다. 이 가이드는 이러한 이유로 Ollama는 항상 네이티브로, Docker는 파이썬 실습 환경(JupyterLab)에만 사용하는 구조를 채택한다.

2Ollama 설치와 API 활용 (모든 경로 공통)

이 섹션의 설치 과정은 경로 A(완전 로컬)와 경로 B(Docker+JupyterLab) 모두에 공통으로 필요하다. Docker를 사용하더라도 Ollama 자체는 반드시 아래 절차대로 각 PC에 네이티브로 설치한다.

STEP 2.1운영체제별 Ollama 설치

Windows

공식 사이트에서 설치 파일 다운로드 후 실행 (더블클릭 설치)

https://ollama.com/download/windows

macOS

Homebrew 또는 공식 설치 파일(.dmg) 사용

brew install ollama

Linux

공식 설치 스크립트 실행 (터미널)

curl -fsSL https://ollama.com/install.sh | sh
설치 확인
$ ollama --version
ollama version is 0.x.x

설치가 완료되면 Windows·macOS에서는 Ollama가 트레이(메뉴 막대) 아이콘 형태의 백그라운드 서비스로 자동 실행되며, Linux(curl 설치 스크립트)에서도 대부분 systemd 서비스로 자동 등록되어 함께 시작된다. 두 경우 모두 API 서버가 http://localhost:11434에서 자동으로 대기 상태가 되므로, 일반적인 상황에서는 별도의 서버 실행 명령 없이 바로 API를 호출하면 된다.

API 서버 정상 동작 확인
$ curl http://localhost:11434
Ollama is running
⚠️ "Ollama is running"이 나오지 않는 경우 — ollama serve

일부 Linux 배포판, WSL 환경, 수동(tar) 설치, 또는 서비스가 수동으로 중지된 경우에는 백그라운드 서버가 자동으로 실행되지 않을 수 있다. 이때는 터미널에서 서버를 직접 구동한다.

$ ollama serve
# 이 터미널 창은 서버가 실행되는 동안 계속 열어두어야 하며,
# 다른 명령(pull, run, API 호출 등)은 새 터미널 창에서 실행한다.

반대로 ollama serve: listen tcp: bind: address already in use 오류가 뜬다면, 이는 서버가 이미 백그라운드에서 정상 실행 중이라는 뜻이므로 ollama serve를 또 실행할 필요가 없다 — 바로 ollama run이나 API 호출로 넘어가면 된다.

STEP 2.4Python으로 호출하기

학생 실습에는 아래 두 방식 중 하나를 사용한다. ① 공식 ollama 파이썬 라이브러리 또는 ② OpenAI 호환 엔드포인트(requests) — 이후 5단원 LangChain 실습과의 연계를 고려하면 ①번 방식을 기본으로 채택하는 것을 권장한다.

python — 방법 ① ollama 라이브러리 (권장)
pip install ollama
agent_basic.py
from ollama import chat

response = chat(
    model='qwen3.5:4b',
    messages=[{'role': 'user', 'content': '안녕! 너를 소개해줘.'}],
)
print(response.message.content)
python — 방법 ② OpenAI 호환 엔드포인트
import requests

resp = requests.post(
    "http://localhost:11434/v1/chat/completions",
    json={
        "model": "qwen3.5:4b",
        "messages": [{"role": "user", "content": "안녕! 너를 소개해줘."}]
    }
)
print(resp.json()["choices"][0]["message"]["content"])
💡 교수·학습 팁

Ollama의 OpenAI 호환 엔드포인트(/v1/chat/completions)를 사용하면, 이후 학생들이 유료 상용 API(OpenAI 등)로 전환할 때도 코드 구조를 거의 그대로 재사용할 수 있음을 함께 안내하면 좋다.

3Docker 기반 개발 환경 구축 (JupyterLab 전용)

실습실 전체 PC에 동일한 파이썬 환경을 빠르게 배포하고 싶을 때 Docker를 사용한다. 단, Ollama는 컨테이너화하지 않는다 (이유는 1장 참고). 2장에서 호스트 PC에 네이티브로 설치한 Ollama를 그대로 사용하고, JupyterLab + 에이전트 라이브러리 컨테이너만 Docker로 구성하여 그 컨테이너가 호스트의 Ollama에 접속하는 구조다.

STEP 3.1Docker Desktop 설치

자신의 운영체제에 해당하는 절차를 순서대로 따라 한다. 세 OS 모두 마지막에 docker run hello-world로 정상 설치를 확인한다.

Windows 10/11

  1. ① 가상화 활성화 여부 확인Ctrl+Shift+Esc로 작업 관리자 실행 → 성능 탭 → CPU → 하단의 가상화 항목이 사용으로 표시되는지 확인. 사용 안 함이면 재부팅 후 BIOS/UEFI 설정에서 Intel VT-x 또는 AMD-V를 켠다.
  2. ② WSL2 설치관리자 권한으로 PowerShell을 열고(시작 메뉴에서 PowerShell 우클릭 → "관리자 권한으로 실행") 아래 명령 실행 후 PC 재부팅
PowerShell (관리자)
wsl --install
  1. ③ Docker Desktop 설치 파일 다운로드docker.com/products/docker-desktop에서 Windows용 Docker Desktop Installer.exe 다운로드
  2. ④ 설치 진행다운로드한 설치 파일을 더블클릭 실행 → 안내 화면에서 "Use WSL 2 instead of Hyper-V" 옵션이 체크되어 있는지 확인(기본값) → 설치 완료 후 PC 재시작
  3. ⑤ 최초 실행재부팅 후 Docker Desktop 자동 실행 또는 시작 메뉴에서 직접 실행 → 라이선스 동의 → Docker Hub 로그인 화면은 건너뛰기(Skip) 가능 (수업 실습에는 로그인 불필요)
  4. ⑥ 정상 실행 확인화면 하단(트레이)에 고래 모양 Docker 아이콘이 나타나고 앱 좌측 하단에 "Engine running"(초록불)이 표시되면 준비 완료

macOS

  1. ① 칩 종류 확인화면 왼쪽 위 Apple 메뉴 → "이 Mac에 관하여"에서 Apple Silicon(M1~M5)인지 Intel인지 확인 (2020년 이후 구매한 Mac은 대부분 Apple Silicon)
  2. ② Docker Desktop 다운로드docker.com/products/docker-desktop에서 자신의 칩에 맞는 Mac용 .dmg 파일 선택(Apple Silicon / Intel 버튼 구분됨)을 다운로드
  3. ③ 설치다운로드된 Docker.dmg 실행 → 뜨는 창에서 Docker 고래 아이콘을 Applications 폴더 아이콘 위로 드래그하여 설치
  4. ④ 최초 실행Finder → 응용 프로그램(Applications)에서 Docker 실행 → "인터넷에서 다운로드한 앱입니다. 여시겠습니까?" 확인 창에서 열기 → 시스템 권한 요청 시 관리자 암호 입력
  5. ⑤ 정상 실행 확인화면 상단 메뉴 막대에 고래 아이콘이 나타나고, 클릭했을 때 "Engine running"(초록불)이 표시될 때까지 대기 (최초 실행 시 수십 초 소요)

Linux (Ubuntu/Debian 계열 기준)

Linux는 별도의 "Docker Desktop" 앱 대신 Docker Engine을 명령줄로 설치한다 (GUI가 필요하면 Docker Desktop for Linux도 별도 제공되지만, 실습실 서버 환경에서는 Engine 설치를 권장한다).

terminal — ① 기존 구버전 제거(있는 경우만)
sudo apt-get remove docker docker-engine docker.io containerd runc
terminal — ② 저장소 등록에 필요한 패키지 설치
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
terminal — ③ Docker 공식 GPG 키 및 저장소 등록
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
terminal — ④ Docker Engine + Compose 플러그인 설치
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
terminal — ⑤ sudo 없이 docker 명령 사용하기 (선택)
sudo usermod -aG docker $USER
# 적용을 위해 로그아웃 후 다시 로그인 (또는 newgrp docker 실행)
💡 모든 OS 공통 — 설치 확인 (마지막 단계)

세 운영체제 모두 아래 세 명령이 오류 없이 실행되면 설치가 정상적으로 끝난 것이다.

$ docker --version
Docker version 2x.x.x, build xxxxxxx

$ docker compose version
Docker Compose version v2.x.x

$ docker run hello-world
Hello from Docker!
This message shows that your installation appears to be working correctly.

docker run hello-world는 아주 작은 테스트 이미지를 내려받아 실행해 보는 명령으로, "Hello from Docker!" 메시지가 뜨면 이미지 다운로드·컨테이너 실행이 모두 정상 작동한다는 뜻이다.

STEP 3.2호스트 Ollama를 컨테이너에서 접근 가능하도록 설정

Ollama는 기본적으로 127.0.0.1(localhost)에서만 요청을 받기 때문에, 이 상태로는 Docker 컨테이너(별도의 네트워크 네임스페이스)에서 접속할 수 없다. 컨테이너가 접속할 수 있도록 호스트의 Ollama가 모든 인터페이스(0.0.0.0)에서 대기하도록 설정을 바꿔야 한다.

Windows

명령 프롬프트(관리자)에서 시스템 환경 변수 등록 후 Ollama 재시작

setx OLLAMA_HOST "0.0.0.0:11434"

macOS

터미널에서 launchd 환경 변수 등록 후 Ollama 재시작

launchctl setenv OLLAMA_HOST "0.0.0.0:11434"

Linux

systemd 서비스 오버라이드 설정 후 데몬 재적용

sudo systemctl edit ollama
macOS — 전체 명령
$ launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
# 메뉴 막대의 Ollama 아이콘에서 Quit 후 다시 실행 (또는 재로그인)
# 참고: 이 설정은 재부팅 시 초기화되므로, 매번 반복하기 번거롭다면
# 로그인 시 자동 실행되는 스크립트(예: launchd plist)에 등록해 두는 것을 권장한다
Windows — 전체 명령
C:\> setx OLLAMA_HOST "0.0.0.0:11434"
:: 명령 실행 후 새 터미널을 열거나 PC를 재시작해야 반영됨
:: 트레이 아이콘에서 Ollama 종료 후 재실행해도 됨
Linux — 전체 명령
$ sudo systemctl edit ollama
# 에디터가 열리면 아래 내용을 입력하고 저장
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"

$ sudo systemctl daemon-reload
$ sudo systemctl restart ollama
💡 그 외에 자주 함께 조정하는 환경 변수

STEP 3.5Dockerfile 작성

아래 WORKDIR /workspace는 호스트의 notebooks/ 폴더가 마운트되는 컨테이너 내부 작업 경로다 (STEP 3.3 참고). 이 이미지에는 Ollama가 포함되지 않는다 — JupyterLab과 에이전트 라이브러리만 담는다.

💡 왜 slim 이미지를 사용하는가

python:3.12(기본 버전)은 컴파일 도구·문서 등이 모두 포함되어 용량이 약 900MB~1GB에 달한다. python:3.12-slim은 Python 실행에 꼭 필요한 최소 구성만 남겨 약 120~150MB로 크기를 줄인 버전이다. 더 작은 alpine 계열은 musl libc 기반이라 sentence-transformers·chromadb·faiss-cpu처럼 C 확장에 의존하는 패키지가 설치 오류를 일으키는 경우가 많아 사용하지 않는다.

slim 이미지에는 컴파일 도구가 빠져 있으므로, 아래 build-essential 설치 줄에서 필요한 만큼만 직접 추가해 준다. 이렇게 하면 일부 패키지의 소스 빌드도 문제없이 되면서 최종 이미지 크기는 작게 유지된다 — 실습실 여러 대에 같은 이미지를 배포할 때 다운로드·빌드 시간을 줄이는 데 특히 유리하다.

Dockerfile
FROM python:3.12-slim

WORKDIR /workspace

# 빌드에 필요한 기본 패키지 설치
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential curl git \
    && rm -rf /var/lib/apt/lists/*

# 파이썬 패키지 설치
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

EXPOSE 8888

# 토큰 없이 바로 접속 가능하도록 설정 (교실 실습용, 외부 배포 시에는 보안 설정 필요)
CMD ["jupyter", "lab", "--ip=0.0.0.0", "--port=8888", \
     "--no-browser", "--allow-root", "--ServerApp.token=''"]
🔒 보안 유의사항

위 설정은 교실 내부망 실습 전용이다. 토큰(--ServerApp.token='')을 비워두면 누구나 접속 가능하므로, 학교 밖 네트워크나 인터넷에 노출되는 서버에는 절대 이 설정을 사용하지 않는다.

                                                           #  포함해 두면 세 플랫폼 모두 동일한 파일로 동작한다)
💡 호스트 Ollama에 접속하는 핵심 개념 — host.docker.internal

컨테이너 안에서 localhost는 컨테이너 자기 자신을 가리키므로, 호스트 PC에 설치된 Ollama에는 localhost로 접속할 수 없다. Docker가 제공하는 특수 DNS 이름 host.docker.internal을 사용해야 컨테이너에서 호스트 머신으로 연결된다.

  • Windows·macOS (Docker Desktop) — host.docker.internal이 기본 제공되어 별도 설정 없이 바로 동작한다.
  • Linux (Docker Engine) — 기본적으로는 정의되어 있지 않으므로, 위 extra_hosts 설정(host-gateway, Docker 20.10+)이 반드시 필요하다.
⚠️ 그래도 연결이 안 될 때 — 방화벽 확인

STEP 3.2에서 OLLAMA_HOST=0.0.0.0으로 설정했는데도 컨테이너에서 연결이 안 되면, 호스트 방화벽이 Docker 브리지 네트워크에서 오는 트래픽을 차단하고 있을 가능성이 있다.

# Linux (ufw 사용 시) — Docker 브리지에서 11434 포트로 들어오는 트래픽 허용
$ sudo ufw allow in on docker0 to any port 11434 proto tcp

# Windows — Windows Defender 방화벽에서 Ollama 관련 인바운드 규칙이 "허용"으로 되어 있는지 확인
# (최초 실행 시 뜨는 방화벽 허용 팝업에서 '허용'을 눌러야 함)

증상원인해결 방법
포트 11434 / 8888 충돌 다른 프로그램이 이미 해당 포트 사용 중 docker-compose.yml의 ports를 "18888:8888" 처럼 왼쪽 값만 변경
모델 다운로드가 매우 느림 최초 1회 3.4GB 다운로드, 실습실 네트워크 병목 수업 전 미리 pull 완료해 두기, 또는 하나의 PC에서 받은 모델 파일을 공유 캐시로 활용
Jupyter에서 Ollama 연결 실패 (Connection refused) 호스트 주소를 localhost로 잘못 지정, 또는 호스트 Ollama가 0.0.0.0으로 재시작되지 않음 컨테이너에서는 host.docker.internal을 host로 사용해야 하며 (STEP 3.6 참고), 호스트 Ollama도 OLLAMA_HOST=0.0.0.0:11434로 재시작되어 있어야 함 (STEP 3.2 참고)
로컬(비-Docker) 환경에서 curl http://localhost:11434가 응답하지 않음 백그라운드 서버가 자동 시작되지 않음 (일부 Linux 배포판·WSL·수동 설치) 터미널에서 ollama serve를 직접 실행하고, 해당 창을 열어둔 채로 다른 터미널에서 ollama run/API 호출 진행
ollama serve: listen tcp: bind: address already in use 오류 서버가 이미 백그라운드에서 정상 실행 중 오류가 아니라 정상 상태 — ollama serve를 또 실행하지 말고 바로 API 호출로 진행
OLLAMA_HOST를 0.0.0.0으로 바꿨는데 Docker 컨테이너에서 여전히 연결 안 됨 호스트 방화벽이 Docker 브리지 네트워크의 트래픽을 차단 Linux는 sudo ufw allow in on docker0 to any port 11434 proto tcp, Windows는 방화벽 인바운드 규칙 허용 확인 (STEP 3.6 참고)
Linux Docker Engine에서 host.docker.internal을 찾을 수 없음 Mac/Windows의 Docker Desktop과 달리 Linux Docker Engine은 이 DNS 이름을 기본 제공하지 않음 docker-compose.yml에 extra_hosts: ["host.docker.internal:host-gateway"] 추가 (Docker 20.10+ 필요, STEP 3.6 참고)
Windows에서 메모리 부족 오류 WSL2 기본 메모리 제한 사용자 홈 폴더에 .wslconfig 파일 생성 후 memory=8GB 등으로 조정, WSL 재시작(wsl --shutdown)
모델 추론 속도가 느림 (macOS) Ollama가 Docker 컨테이너 안에서 실행 중이라 Metal GPU를 사용하지 못하고 CPU로 동작 본 가이드대로 Ollama를 호스트에 네이티브 설치했다면 발생하지 않음. 혹시 과거에 Ollama를 컨테이너로 띄운 적이 있다면 해당 컨테이너를 제거하고 STEP 2의 네이티브 설치로 전환
GPU가 활용되지 않는 것 같음 Ollama가 네이티브로 설치되어 있다면 자동 감지되지만, 드라이버가 오래된 경우 CPU로 폴백될 수 있음 Windows/Linux는 최신 NVIDIA 드라이버 설치 확인, Mac은 ollama ps로 PROCESSOR 항목이 GPU로 표시되는지 확인 (GPU 없이도 4B 모델은 CPU로 정상 동작)
Jupyter 접속 시 토큰/비밀번호 요구 Dockerfile의 CMD 옵션이 반영되지 않음 (캐시된 이미지 사용 중) docker compose build --no-cache jupyter 로 이미지 재빌드

아래 세 예제는 난이도 순으로 배치되어 있으며, 5단원 성취기준 [12인프05-01]~[12인프05-03]과 직접 연결된다. 모든 예제는 위에서 구축한 환경(경로 A 완전 로컬, 경로 B Docker+JupyterLab) 어느 쪽에서도 그대로 실행 가능하다 — 단, 경로 B에서는 ollama.Client(host=...)의 host 값을 http://host.docker.internal:11434로 지정한다.

예제 1

기본 대화형 챗봇 에이전트

목표: LLM API 호출 구조와 대화 이력(messages) 관리 원리를 이해한다.

사용자 입력→ 대화 이력에 추가→ ollama.chat() 호출→ 응답 출력·이력 저장
ex1_basic_chatbot.py
import ollama

MODEL = "qwen3.5:4b"
history = [
    {"role": "system", "content": "너는 친절한 한국어 AI 에이전트 튜터야."}
]

print("챗봇을 시작합니다. 종료하려면 'exit'을 입력하세요.\n")

while True:
    user_input = input("나: ")
    if user_input.strip().lower() == "exit":
        break

    history.append({"role": "user", "content": user_input})
    response = ollama.chat(model=MODEL, messages=history)
    reply = response.message.content

    print(f"AI: {reply}\n")
    history.append({"role": "assistant", "content": reply})
💡 학습 포인트

history 리스트에 이전 대화를 계속 누적해야 모델이 문맥을 기억한다는 점, 그리고 system 역할로 에이전트의 페르소나를 지정할 수 있다는 점을 강조한다.

예제 2

도구 호출(Tool Use) 에이전트 — 계산기 · 날씨 · 검색

목표: 여러 개의 도구 중에서 LLM이 질문에 맞는 도구를 스스로 선택·호출하는 AI 에이전트의 핵심 원리를 체험한다.

질문 입력→ 모델이 도구 설명을 보고 필요한 도구 판단→ calculate / get_weather / web_search 중 실행→ 결과를 답변에 반영
📌 에이전트는 어떻게 도구를 "선택"하는가

모델은 tools 리스트에 담긴 각 도구의 이름(name)·설명(description)·매개변수(parameters)를 읽고, 사용자 질문의 의미와 가장 잘 맞는 도구를 스스로 판단해 고른다. 별도의 if-else 분기문을 개발자가 작성하는 것이 아니라, 도구 설명 자체가 모델의 판단 근거가 된다는 점이 핵심이다.

  • 도구가 여러 개 주어져도 모델은 질문에 맞는 도구 하나(또는 필요한 만큼)만 선택하고 나머지는 무시한다.
  • 어떤 도구도 필요 없는 질문(예: 일상 대화)에는 tool_calls 없이 바로 텍스트로 답변한다.
  • description을 얼마나 명확하게 쓰느냐가 선택 정확도를 좌우한다. "날씨를 알려주는 도구"처럼 애매하게 쓰면 계산 질문에도 날씨 도구를 잘못 선택하는 경우가 생길 수 있다.

확장 활동 제안 — 학생들에게 일부러 두 도구의 description을 비슷하게(애매하게) 바꿔보게 한 뒤, 같은 질문에 모델이 엉뚱한 도구를 선택하는 것을 관찰시키면 "도구 설명이 곧 모델과의 인터페이스"라는 점을 체감하는 좋은 실습이 된다.

ex2_tool_calling_agent.py
import ollama

MODEL = "qwen3.5:4b"

# ── 도구 함수 정의 ──────────────────────────────

def calculate(expression: str) -> str:
    """안전한 범위 내에서 사칙연산 수식을 계산하는 도구 함수"""
    try:
        allowed = "0123456789+-*/(). "
        if not all(ch in allowed for ch in expression):
            return "오류: 허용되지 않은 문자가 포함되어 있습니다."
        return str(eval(expression, {"__builtins__": {}}))
    except Exception as e:
        return f"오류: {e}"

def get_weather(city: str) -> str:
    """도시별 날씨를 반환하는 모의(mock) 도구.
    실습 편의를 위해 고정된 데이터를 사용한다.
    실제 서비스에서는 기상청 API나 OpenWeatherMap 같은 외부 API를 호출하면 된다."""
    mock_weather = {
        "서울": "맑음, 22도",
        "부산": "흐림, 19도",
        "대구": "맑음, 25도",
        "제주": "비, 18도",
    }
    return mock_weather.get(city, f"'{city}'의 날씨 정보를 찾을 수 없습니다.")

def web_search(query: str) -> str:
    """간단한 지식 베이스에서 검색하는 모의(mock) 도구.
    실습 편의를 위해 미리 준비한 데이터에서 찾는다.
    실제 서비스에서는 검색 엔진 API를 호출하면 된다."""
    mock_index = {
        "트랜스포머": "트랜스포머는 2017년 논문에서 제안된 딥러닝 구조로, 어텐션 메커니즘을 기반으로 한다.",
        "인공지능 에이전트": "인공지능 에이전트는 목표를 이해하고 행동을 선택해 문제를 해결하는 프로그램이다.",
        "라마": "라마(Llama)는 Meta가 공개한 오픈소스 대규모 언어 모델 계열이다.",
    }
    for keyword, content in mock_index.items():
        if keyword in query:
            return content
    return "관련 정보를 찾을 수 없습니다."

# 도구 이름 → 실제 함수를 연결하는 매핑
TOOL_FUNCTIONS = {
    "calculate": calculate,
    "get_weather": get_weather,
    "web_search": web_search,
}

# ── 모델에게 제공할 '도구 명세서' (설명이 선택 정확도를 좌우한다) ──

tools = [
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "사칙연산이 포함된 수학 수식 문자열을 계산하여 숫자 결과를 반환한다.",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": '계산할 수식. 예: "3*7+2"'}
                },
                "required": ["expression"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "특정 도시의 현재 날씨(날씨 상태와 기온)를 조회한다.",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": '날씨를 확인할 도시 이름. 예: "서울"'}
                },
                "required": ["city"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "web_search",
            "description": "모델이 알지 못하는 개념이나 최신 정보를 찾기 위해 지식 베이스를 검색한다.",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "검색할 키워드나 질문"}
                },
                "required": ["query"],
            },
        },
    },
]

# ── 에이전트 실행 루프 (여러 번의 도구 호출도 처리) ──

def run_agent(user_question: str, max_turns: int = 5):
    messages = [{"role": "user", "content": user_question}]

    for _ in range(max_turns):
        response = ollama.chat(model=MODEL, messages=messages, tools=tools)

        # 모델이 더 이상 도구가 필요 없다고 판단하면 최종 답변 출력 후 종료
        if not response.message.tool_calls:
            print("AI 답변:", response.message.content)
            return

        messages.append(response.message)

        for call in response.message.tool_calls:
            func = TOOL_FUNCTIONS.get(call.function.name)
            if func is None:
                result = f"알 수 없는 도구 호출: {call.function.name}"
            else:
                result = func(**call.function.arguments)  # 모델이 고른 도구를 실제로 실행

            print(f"[도구 실행] {call.function.name}({call.function.arguments}) → {result}")
            messages.append({"role": "tool", "content": str(result), "name": call.function.name})

    print("최대 반복 횟수에 도달했습니다.")

# ── 실행 예시: 질문마다 서로 다른 도구가 선택되는 것을 관찰한다 ──
run_agent("3 곱하기 7 더하고 2를 더하면 얼마야?")   # → calculate 선택
run_agent("오늘 대구 날씨 어때?")                     # → get_weather 선택
run_agent("트랜스포머에 대해 알려줘")                  # → web_search 선택
run_agent("너는 이름이 뭐야?")                         # → 도구 없이 바로 답변
⚠️ 안전한 실습을 위한 유의사항

실제 서비스에서는 eval()을 직접 사용하지 않는다. 위 코드는 교육용으로 허용 문자를 제한했지만, 학생들에게 "왜 임의의 코드 실행이 위험한가"를 함께 토론시키는 것이 5단원 윤리 성취기준([12인프05-03])과 자연스럽게 연결된다. get_weather·web_search도 실습 편의상 고정된 데이터로 흉내 낸 모의(mock) 도구이며, 실제 API로 교체하는 것은 좋은 확장 과제가 된다.

예제 3

미니 RAG(검색 증강 생성) 에이전트

목표: 문서 임베딩 → 유사도 검색 → 프롬프트 결합의 RAG 파이프라인을 직접 구현하며 환각 현상을 줄이는 원리를 체험한다.

문서 임베딩→ 질문 임베딩→ 코사인 유사도 계산→ 관련 문서를 프롬프트에 삽입→ LLM 답변 생성
ex3_mini_rag_agent.py
import numpy as np
import ollama
from sentence_transformers import SentenceTransformer

MODEL = "qwen3.5:4b"

# 1. 지식 베이스(문서) 준비 — 실습에서는 학생이 직접 교과 내용으로 교체 가능
documents = [
    "트랜스포머는 2017년 논문 'Attention Is All You Need'에서 처음 제안된 구조이다.",
    "합성곱 신경망(CNN)은 이미지의 공간적·지역적 특징을 계층적으로 추출한다.",
    "GPU는 대규모 병렬 연산에 최적화되어 있어 딥러닝 훈련 속도를 크게 높여준다.",
    "RAG는 검색으로 찾은 문서를 LLM의 답변 생성 과정에 결합하는 기법이다.",
]

# 2. 문서 임베딩 (다국어 지원 경량 모델 사용)
embedder = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
doc_embeddings = embedder.encode(documents)

def retrieve(query: str, top_k: int = 1):
    query_embedding = embedder.encode([query])[0]
    # 코사인 유사도 계산
    scores = np.dot(doc_embeddings, query_embedding) / (
        np.linalg.norm(doc_embeddings, axis=1) * np.linalg.norm(query_embedding)
    )
    top_idx = np.argsort(scores)[::-1][:top_k]
    return [documents[i] for i in top_idx]

def rag_answer(query: str):
    context = retrieve(query, top_k=1)[0]

    prompt = f"""다음 참고 문서를 바탕으로 질문에 정확하게 답하세요.
문서에 없는 내용은 추측하지 말고 "문서에서 확인할 수 없습니다"라고 답하세요.

[참고 문서]
{context}

[질문]
{query}

[답변]"""

    response = ollama.chat(model=MODEL, messages=[{"role": "user", "content": prompt}])
    print("검색된 문서:", context)
    print("AI 답변:", response.message.content)

rag_answer("트랜스포머는 언제, 어떤 논문에서 등장했나요?")
📌 확장 활동 제안

학생들에게 documents 리스트를 각자 관심 있는 타 교과(생명과학, 화학 등) 문단 5~10개로 교체하게 하면, 5단원의 "맞춤형 논문 분석 에이전트" 프로젝트로 자연스럽게 확장할 수 있다.
