개발 방향

대규모 언어 모델(LLM)의 기초에서 출발하여, 에이전트의 개념과 도구 사용, 외부 정보 활용, 계획 기반 문제 해결로 단계적으로 확장한다. 특정 프레임워크의 사용법보다 오래 유지되는 핵심 개념과 문제 해결 경험을 중심으로 구성한다.

교과목 설계 원칙

과목의 정체성

“AI 모델을 직접 학습시키는 방법”보다 “AI를 활용하여 실제 문제를 해결하는 프로그램을 어떻게 설계할 것인가”에 초점을 둔다.

학습자의 출발점

  • 고등학생이 LLM이나 AI 에이전트를 처음 접할 수 있음을 전제로 한다.
  • 1단원에서 생성형 AI와 LLM의 최소한의 원리를 이해한 뒤 에이전트 개념으로 이동한다.
  • 기존 정보 교과의 함수, 조건, 반복, 문제 분해 개념을 Agent Programming과 연결한다.

교과서의 수명을 확보하는 방법

  • LangChain, 특정 모델명, 특정 API를 핵심 개념으로 고정하지 않는다.
  • 목표, 행동, 도구, 정보 검색, 계획과 같이 기술이 바뀌어도 유지되는 개념을 본문 중심으로 다룬다.
  • MCP, Multi-agent 등 빠르게 변하는 기술은 “더 알아보기 / 심화 탐구” 코너에서 선택적으로 소개한다.

윤리와 신뢰성의 배치

  • 별도의 5단원으로 분리하기보다 각 단원에 “책임 있는 AI 코너”를 배치한다.
  • 환각과 검증, 외부 도구의 권한, 출처와 저작권, 인간의 최종 확인 등을 해당 맥락에서 다룬다.
성취기준 코드 표기 방식 — [12인에01-01]과 같이 학교급(12=고등학교) + 과목 약칭(인에=인공지능에이전트프로그래밍, 잠정) + 영역 번호(대단원 순서, 01~05) + 일련번호 순으로 표기했다. 과목 약칭 “인에”는 2022 개정 교육과정의 다른 정보과 과목(예: 인공지능 기초 → 인기) 표기 관행을 참고한 잠정안이며, 과목이 정식 인정·고시되면 확정된 약칭으로 교체해야 한다. 최소 성취수준은 3단계 성취평가(A/B/C) 진로선택과목 기준 C수준을 “주어진 절차를 따라 실행·설명할 수 있는 최소 능력”으로 진술했다.

논의가 필요한 문제 · 교과서의 수명을 확보하는 방법과 연계

실습용 파이썬 코드를 어떻게 전달·작성·실행하게 할 것인가?

에이전트 프로그래밍 실습은 결국 파이썬 코드를 다루는 것을 전제로 한다. 그런데 이 코드를 학생에게 어떤 형태로 제시하고, 어디까지 직접 작성하게 하며, 어떤 환경에서 실행하게 할 것인지는 이번 초안에 아직 반영되어 있지 않다. 특정 도구나 환경에 얽매이지 않으려는 설계 원칙과, 실제 수업에서는 구체적인 도구를 정해야 하는 현실 사이의 간극이 가장 크게 드러나는 지점이므로 별도의 논의가 필요하다.

  • 코드 전달 방식 — 교과서에 전체 코드를 인쇄할지, 빈칸을 채우는 스타터 코드를 제공할지, 완성 코드를 배포하고 읽고 수정하는 것부터 시작할지 결정이 필요하다.
  • 학생이 직접 작성하는 범위 — 함수 내부 로직까지 작성하게 할지, 이미 만들어진 함수를 조합·호출하는 수준으로 제한할지 단원별로 다르게 가져갈 수 있다.
  • 실행 환경 — 로컬 설치, Google Colab, 웹 기반 실습 도구(교육용 IDE) 중 학교 현장에서 안정적으로 쓸 수 있는 방식을 검토해야 한다.
  • 학교 현장의 제약 — 기기·인터넷 환경 편차, 소프트웨어 설치 권한, 수업 시수 안에서 환경 설정에 드는 시간까지 함께 고려해야 한다.
  • Vibe coding과의 관계 — 단원 말미 “AI 보조 실습”에서 다루는 AI 생성 코드 검증 활동과, 단원 본문에서 학생이 직접 작성하는 코드의 난이도·분량을 어떻게 연결할지도 함께 정리가 필요하다.

Unit 01

인공지능과 대규모 언어 모델의 이해

핵심 질문 ChatGPT와 같은 인공지능은 어떻게 사람의 말을 바탕으로 답을 만들어 낼까?
핵심 아이디어 대규모 언어 모델은 많은 텍스트에서 언어의 패턴을 학습하여 입력에 이어질 내용을 생성하며, 외부 정보와 도구를 연결하면 에이전트의 핵심 구성 요소가 될 수 있다.
지식·이해

인공지능과 생성형 AI, 학습과 사용(추론)의 차이, 토큰, 언어 모델의 생성 원리, 프롬프트와 맥락(Context), LLM의 한계와 환각(Hallucination), 학습 데이터의 편향(Bias)

과정·기능

간단한 프롬프트를 설계하고 출력 결과를 비교하기, 동일한 질문에 대한 결과를 관찰하기, 프로그램에서 LLM을 호출하는 기본 흐름 이해하기

가치·태도

생성 결과를 그대로 믿지 않고 확인하며, LLM이 모르는 정보와 만들어 낸 정보를 구분하려는 태도, 과도한 의존을 경계하고 스스로 생각하려는 태도

Unit 02

인공지능 에이전트의 이해

핵심 질문 질문에 답하는 인공지능과 스스로 일을 수행하는 인공지능은 무엇이 다를까?
핵심 아이디어 인공지능 에이전트는 목표를 이해하고, 필요한 행동을 선택하며, 행동의 결과를 확인한 뒤 다음 행동을 결정하는 과정을 반복하여 문제를 해결한다.
지식·이해

LLM과 AI 에이전트의 차이, 목표(Goal), 행동(Action), 관찰/결과(Observation), Agent Loop와 종료 조건(Termination Condition), 자율성 수준과 인간 개입 지점(Human-in-the-loop), 일반 프로그램과 에이전트 프로그램의 차이

과정·기능

문제를 목표와 작은 작업으로 나누기, 상황에 따라 행동을 선택하기, 행동 결과를 확인하고 다음 행동을 결정하는 흐름 설계하기, 반복이 길어지거나 실패할 때 중단·재시도하는 처리 설계하기

가치·태도

AI에게 맡길 수 있는 일과 사람이 확인해야 하는 일을 구분하고, 결과를 검증하려는 태도

대표 학습 활동 수행평가 일정을 정리하는 에이전트

“이번 주 수행평가 일정을 정리해 줘”라는 목표를 바로 답하는 문제가 아니라 여러 행동을 거쳐 해결하는 문제로 바꾸어 본다.

목표: 이번 주 수행평가 일정 정리
↓
학교 일정에서 수행평가 정보 확인
↓
과목별 일정 추출
↓
날짜순으로 정리
↓
결과를 확인하고 학생에게 제시
수업 포인트 — 에이전트는 “한 번의 답변”이 아니라 목표를 달성하기 위한 여러 행동의 흐름이라는 점을 이해한다.
Agent Loop를 한 문장으로 — 목표 확인 → 무엇을 할지 결정 → 행동 → 결과 확인 → 필요하면 다시 행동
